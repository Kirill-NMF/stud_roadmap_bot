# Non-IT Staging Checklist

Use this later when we are ready to imitate a non-developer installation from the console.

## Goal

Validate that one command plus guided inputs can deploy the project without conflicting with existing VPS projects.

## Test Preconditions

- Production pipeline is already running and must not be interrupted.
- We are using staging paths and dry-run flags.
- We do not register Telegram webhook with the production bot.
- We do not register or trigger production Notion webhook.
- We do not reload live Caddy.
- We do not overwrite live systemd units.

## Staging Inputs

Use placeholders or approved real values:

```text
DOMAIN=roadmap-test.example.com
TELEGRAM_BOT_TOKEN=<production token only for getMe, or separate test token>
TELEGRAM_WEBHOOK_SECRET=<generated by wizard>
TELEGRAM_CHAT_ID=<optional; only if sending approved test message>
NOTION_API_KEY=<production token only for read check, or separate test token>
NOTION_TARGET=<test page preferred>
OPENROUTER_API_KEY=<real key allowed for tiny test call>
ROADMAP_PUBLIC_BASE_URL=https://roadmap-test.example.com/roadmap-reader
```

## Planned Command Shape

The future command should look like:

```bash
curl -fsSL https://raw.githubusercontent.com/Kirill-NMF/stud_roadmap_bot/main/scripts/bootstrap_ubuntu.sh | \
  sudo bash -s -- \
  --staging-root /tmp/stud-roadmap-install-test \
  --dry-run \
  --no-systemd \
  --no-caddy-reload \
  --no-webhooks
```

The interactive wizard should then ask for values one by one.

## Expected Wizard Flow

1. Shows what will be installed.
2. Shows mode: staging/dry-run.
3. Asks for domain.
4. Validates domain format.
5. Asks for Telegram bot token with hidden input.
6. Offers to generate Telegram webhook secret.
7. Asks for Telegram chat id or allows skipping.
8. Asks for Notion token with hidden input.
9. Asks for Notion page URL.
10. Asks for OpenRouter API key with hidden input.
11. Shows summary without printing secrets.
12. Asks for final confirmation.
13. Writes staging env with `0600` permissions.
14. Renders Caddyfile into staging root.
15. Renders systemd units into staging root.
16. Runs passive checks if enabled.
17. Runs doctor.
18. Prints next manual steps.

## Acceptance Criteria

- No production files changed.
- No production services restarted.
- No Telegram webhook changed.
- No Notion page writes happened.
- No secrets printed in logs.
- Generated env exists and has mode `0600`.
- Generated Caddyfile contains the test domain.
- Generated systemd units point to staging paths or are only rendered, not installed.
- Doctor finishes with clear pass/fail output.
- The user-facing output tells a non-developer exactly what to do next.
